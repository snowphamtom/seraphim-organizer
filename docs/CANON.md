> **2026-09-27 no silent drops + doc/code-aware classifier (polish only; hero and input unchanged):** Every non-blank line is sorted, including lines that start with `#` (markdown headings, code comments). The only line ever skipped is an exact `> sort` command line, and the status line counts it ("· 1 command line skipped"; lines over the 4,000-line cap are counted the same way), so lanes + reported skips = non-blank input lines. Exports keep each full line. When a tray has more than 400 rows, it ends with a "+N more in the download (organized … · hold … · watch …)" note, so rows past the cap (WATCH included) are counted by lane. Classifier changes: (1) ALL-CAPS only counts as spam for long shouting prose (≥7 plain caps words, not a heading, label, table row, document marking or code), so short headings, CONFIDENTIAL-style markings, CONSTANT_CASE identifiers and part-number rows are no longer REFUSE. (2) "no vowels"/gibberish never fires on code (`_ . ( ) =` etc.) or on a line with a real vowel word; keyboard mash and repeated letters are still NOISE. (3) Reasons: symbol-only lines are NOISE/"no words", one-letter lines NOISE/"too short"; "empty" is only for blank input; a bare date/timestamp is a thin note (HOLD). (4) An exact (normalized: case, whitespace, punctuation) duplicate of ANY earlier line is ASIDE, even when the first copy went to NOISE or REFUSE. Refused/noise lines are remembered case-sensitively, so a refused SHOUTING copy still never turns the later normal-case original into a duplicate (the Sep 27 caps-dupe behavior holds). Links read as "url" when matching kept lines, so a repost with a new short link is still a duplicate. (5) Near-duplicates now only cover whitespace/punctuation/case differences, or ≤2 edited characters on long lines (≥40 chars) with identical digits, so lines that differ in a word, name, identifier, number or path are kept. The old 80% word-overlap rule is gone. (6) `12x`-style counts only count as spam next to hype words (`next 100x`, `10x gains`), so file listings and parts rows with ids are not spam without another signal. (7) Identifiers (P0, Q3), 3+ digit numbers after a real word, and the parts of code identifiers count as words, so reference notes like "refs: 1234 → 5678" and short code lines are ORGANIZED instead of HOLD. @handles and #tags are not code. Tests: `seraphim-work/test-classifier.js` 124/124 (73 prior cases, two with updated expectations for (4): an exact repeat of spam or mash is now ASIDE instead of REFUSE/NOISE), `test-browser.js` 58/58.

> **2026-09-27 classifier hardening (polish only; hero and input unchanged):** Duplicates are checked before the spam rules and are case-insensitive, so an UPPERCASE copy of an earlier line goes to ASIDE instead of tripping the all-caps rule. Only kept lines (and their duplicates) are remembered, so a refused or noise line never turns a later original into a "duplicate", and repeated spam or mash stays REFUSE or NOISE. New conservative spam rules cover dating spam (hot/local singles) and phishing ("your account has been suspended", "verify/confirm your password/account/identity", unusual sign-in activity, undelivered package, "update your payment details", password expiry). Each phishing phrase is only a hint on its own; two together, or one plus another signal, refuse. Letters in any script (\p{L}: Cyrillic, CJK, Arabic, accented) count as real text, and no-space scripts count as more than one word, so non-English is no longer NOISE/empty. The keyboard-mash heuristics still apply to Latin text. `!!!`, `!!`, `$$` and 🚀💰🤑💸🔥🔥 are now amplifiers: they only add to a line that already has a real spam signal, so they no longer send a normal post to REFUSE or HOLD on their own. Regression cases in `seraphim-work/test-classifier.js` (73/73); browser checks 53/53. Proof: `/workspace/proof/REPORT-v2.md`.
